## 一言説明

釣り竿型の専用コントローラーを用意せず、PCと手元のスマートフォンで遊べる3D Web釣りゲームです。タッチでもモーションでも操作でき、魚ごとの泳ぎ・抵抗・見た目から技術の違いを釣り比べられます。

## 課題と解決方法

### 解決したい課題

並行処理、コンテナ、イベントループといった技術概念は、用語や図だけでは動きや手触りを想像しにくいことがあります。技術ごとの違いを、短い時間で触って比べられる入口を作りたいと考えました。

### 解決方法

釣り専用の竿やコントローラーを追加で用意しなくても、手元のスマートフォンから参加できる手軽さを大切にしました。PCの画面で海や魚を見ながら、スマートフォンはタッチで操作できます。対応端末ではモーション操作も選べ、振る・上へ動かす・回す・手前へ引く動きを、釣りの局面に応じてキャスト・合わせ・リール・竿をあおる操作へ変換します。操作に対する魚の反応は魚種ごとに異なる泳ぎ・抵抗・見た目で表し、釣果は図鑑と技術ツリーで振り返れます。技術の内部動作をそのまま再現するシミュレーターではなく、理解の入口となる比喩として設計しています。

### 想定する利用者・利用シーン

技術用語の説明だけでは違いをつかみにくい学生やWeb展示の来場者を想定しています。PCで海の画面を開き、来場者は手元のスマートフォンでQRコードを読むだけで同じ釣り場に参加できます。釣り専用機器は不要で、タッチ操作ですぐ遊べます。対応端末ではモーション操作も選べるため、展示では気軽さを保ちながら身体を使った体験も見せられます。

## 作ったもの

### プロダクト概要

ブラウザー上の3D釣りゲームです。PCまたは接続したスマートフォンでルアーを投げ、ウキのアタリに合わせ、魚の抵抗と糸の張りを見ながら巻く・緩めるを切り替えて釣り上げます。釣果はプレイヤー別の図鑑に記録されます。

PCは海・魚・竿の変化を見る表示端末、スマートフォンは手元の入力端末として使います。専用の釣り竿型機器を用意する必要はなく、スマートフォンのタッチ操作だけでも遊べます。モーション操作を選んだ場合は端末の動きを操作イベントに変換し、サーバー上の判定結果をPCとスマートフォンへ返すため、入力と反応の対応を追いやすい構成です。スマートフォンが接続された後はスマートフォンを入力担当にし、PCとの同時操作による競合を抑えます。

6種類の魚が、それぞれ異なる技術の比喩になっています。

| 魚 | 表現する考え方 | 泳ぎ・駆け引き・見た目 |
| --- | --- | --- |
| Go魚 | 並行処理 | 警戒して向きを変えた後、突進やラインを横切る動きを見せる。ファイト中に現れる群れは表示上のモデルで、抵抗と捕獲判定は主魚1匹が担う |
| Dockerクジラ | コンテナと実行環境 | 背中にコンテナを載せた大きな魚。重い初動、ゆっくりした旋回、途中の強い突進を組み合わせる |
| CSS fish | 構造と見た目の分離 | コンパクトな魚体の形を保ち、ファイト状態に合わせて色・模様・発光を変える。引きは比較的扱いやすく、短い抵抗の後に回復する |
| K8sレヴィアタン | クラスターとレプリカ | 本体の後を二つの影が追い、突進や水面への動きに合わせて隊形を変える。影は演出で、釣果として数えるのは本体だけ |
| Rustカジキ | 所有権と値の移動 | 青い縦縞と長い吻を持つカジキ。速度のある突進を繰り返し、表層へ跳ねる動きを見せる |
| JSアナゴ | イベントループと非同期処理 | マアナゴをモデルに、胴体から尾まで波打たせて泳ぐ。ファイトでは周期的な突進やコイル状の動きを見せる |

魚種の違いは、見た目だけでなく魚種別の戦闘プロファイルにも反映しています。技術の実装を再現するものではなく、動きや駆け引きを使った比喩です。魚を替えて釣り比べることで、同じ操作でも抵抗や回復の仕方が変わる設計です。

### 技術スタック

- **画面・操作:** React 19、TypeScript、Vite
- **3D表現:** Three.js、WebGL、GLSL
- **音:** Web Audio API
- **スマートフォン入力:** Device Motion API（`devicemotion`）。対応端末で振る・回す・引く動作を入力にし、利用できない場合はタッチ操作へ切り替えます。
- **サーバー:** Node.js 22、Hono、WebSocket（`ws`）、Zod
- **保存:** ローカル開発はSQLite、本番Cloud RunはCloudflare D1。図鑑の捕獲履歴をアプリの再起動後も残すため、プロセス内メモリーではなくD1に保存します。
- **配信:** DockerコンテナをGoogle Cloud Runで配信

### アーキテクチャ・設計

![PC・スマートフォン・サーバー・D1の構成図](assets/architecture.svg)

スマートフォンのセンサー値は端末内で釣り操作イベントへ変換し、生データはサーバーへ送りません。PC画面とスマートフォンは同じ釣り場へWebSocketで接続し、操作イベントをサーバーで検証してキューへ入れます。一回操作は次の固定20Hz tickで順に処理し、リールの押下状態は短い期限付きで更新するため、停止通知が失われても巻きっぱなしにならない設計です。サーバーは魚の位置・抵抗・糸の張り・捕獲判定を進め、状態スナップショットを両画面へ配信します。クライアントは補間して魚、海面、竿、糸を描画します。捕獲時は保存用リポジトリへイベントを渡し、Cloudflare D1へ記録します。

HTTP APIとWebSocketの入力はZodで検証します。釣果はCloudflare D1の捕獲イベントとプレイヤー別集計に保存します。イベントキーの一意制約とトランザクション処理により、同じ捕獲イベントの再送で釣果数が二重に増えないようにしています。

### 設計上の判断

スマートフォン入力、WebSocketルーム、ゲーム規則、図鑑保存の境界を分けたモジュラーモノリスとして構成しました。PCとスマートフォンが別々にゲーム判定する方式は採らず、入力操作イベントをサーバーへ集めて釣り状態と捕獲判定を一元管理します。WebSocketの操作は形式・役割・ゲーム局面を検証し、一回操作は最大16件のキューを通して固定tickで処理します。状態配信ではゲーム判定と表示上の補助モデルを分け、群れや影の演出が釣果数を増やさないようにしています。捕獲イベントは一意キー付きで保存し、再試行で二重計上しない設計です。これはイベントソーシングやメッセージブローカーを使う構成ではありません。ゲームルーム自体はCloud Runプロセス内にあり、図鑑の捕獲履歴とは永続性を分けています。

### 使い方・デモ

1. PCで[Go魚の固定ルート](https://gijutu-turi-e7ranic5ja-an.a.run.app/gofish)を開きます。魚種が固定されるため、デモ中にランダム抽選へ変わりません。
2. 「スマホを接続」を開き、表示されたQRコードをスマートフォンで読み取ります。画面に同じ釣り場が表示されたことを確認します。
3. スマートフォンで「モーション操作を有効にする」を押します。許可された端末では、振って投げる、ウキが沈んだときに上へ振って合わせる、手首を回して巻く操作ができます。魚とのやりとり中に画面を自分へ向け、端末を遠くから手前へ一度引くと、短く巻きながら竿をあおる操作になります。端末は最初のセンサー値を受け取ってから有効状態を表示し、センサー値を取得できない場合は再試行とタッチ操作を案内します。
4. センサーが使えない場合は、スマートフォン画面のボタンを使います。PC単体でも「投げる」「合わせる」「巻く」を操作できます。
5. 釣り上げた後に図鑑を開き、魚の特徴と技術ツリーを見ます。

デモの説明は2〜3分を目安にできます。魚の抵抗や操作により捕獲までの時間は変わります。

### 技術的な見どころ

- **専用機器なしで参加できるスマートフォン操作:** QR接続した手元のスマートフォンを入力に使うため、釣り竿型コントローラーを用意せずに遊べます。基本のタッチ操作に加え、対応端末ではモーション操作を選べます。モーションは釣りの局面に合わせてキャスト・合わせ・リール・竿をあおる操作に変換し、単発のセンサー値で誤作動しないよう複数サンプルで動きを確かめ、一定時間のクールダウンも設けています。センサー許可や取得失敗も画面に伝えます。
- **魚ごとに違う泳ぎと抵抗:** サーバー上の魚種別プロファイルが突進、警戒、回復、横移動、張力、疲労などを変えます。魚の位置と泳ぎの状態を共有し、クライアントは補間して描画します。魚の基準位置・向きはゲーム状態から受け取り、表示側は泳ぎの波や水面演出を滑らかに見せます。
- **見た目を魚の個性と状態へ結びつける表現:** 背中のコンテナを載せたクジラ、状態で色・模様が変わるCSS fish、全身をうねらせるJSアナゴなど、形・泳ぎ・状態演出を組み合わせています。魚の補助モデルは本体と同じ捕獲判定を持つとは限りません。
- **イベント入力と固定tickを組み合わせた通信:** WebSocketの一回操作をZodで検証してキューへ入れ、次の20Hz tickで処理します。PCとスマートフォンには同じ更新済みスナップショットを配信し、捕獲イベントは非同期で保存します。したがって「イベント駆動」は入力・捕獲の扱いを指し、魚の時間進行は固定tickです。
- **バックエンドの責務分離:** ルームと通信、ゲーム規則、コレクション保存の役割を分け、サーバーがゲーム状態を一元管理します。プロセス内ゲーム状態とD1の永続データは別の寿命です。
- **初期表示を優先するモデル準備:** 戦闘に必要な魚を先に読み込み、群れ・残像・レプリカなどの補助モデルはブラウザーのアイドル時間を利用して分割準備する設計です。
- **釣果を残す保存設計:** Cloudflare D1に魚種カタログ、プレイヤーごとの集計、捕獲イベントを保存します。保存失敗時は再試行でき、重複イベントは二重計上しません。

### 一番見てほしいポイント

PCの画面にスマートフォンをQR接続し、釣り専用機器を足さなくても参加できる手軽さをまず体験してください。タッチ操作ですぐ釣りを始められ、対応端末ではモーション操作も選べます。魚を替えると泳ぎ・引き・見た目が変わり、技術ごとの個性を釣り比べられます。その体験を支える入力イベント・サーバー判定・状態配信・釣果保存の責務分担にも注目してください。

## 5つの評価観点に対するアピール

- **プロダクトに対する技術の相当性:** 手元のスマートフォンからのタッチ入力と、選択式のモーション入力（Device Motion API）、二画面の同期（WebSocket）、魚の見た目（Three.js/WebGL）、釣果の永続化（D1）を、それぞれ釣り体験の役割に結びつけています。
- **アーキテクチャ・設計の妥当性:** クライアントで入力と描画、サーバーでゲーム判定、リポジトリで保存を担います。入力イベントは検証後に固定tickで処理し、状態を両画面へ配信します。捕獲イベントは重複を防いで保存し、失敗時に再試行できます。
- **技術的な挑戦度:** 端末モーションを局面に応じた操作へ変換し、その入力を魚種別のゲーム挙動と3D表現へつなぎ、二画面同期と釣果保存まで一連の体験として実装しました。
- **プロダクトの完成度:** 公開URL、魚種別の固定ルート、PC操作、スマートフォン接続、タッチ操作とモーション操作、図鑑への記録を用意しています。モーションセンサーが使えない場合もタッチ操作で遊べます。
- **技術的な面白さ・独自性:** 技術の違いを魚の動きと引きへ対応させ、説明を読むだけでなく、釣り上げる過程を通じて比べられるようにしました。

## 検証状況と利用上の前提

提出用ソースでは、モーション判定、魚種別のゲーム挙動・描画、ルーム入力、D1保存を含む222件の自動テストが通過しています。単発のセンサースパイクを除外する確認、ゲーム局面ごとの魚種別抵抗、捕獲イベント再送時の二重計上防止などをテストしています。TypeScript型チェック、サーバーコンパイル、クライアントの本番ビルドも提出用ソースで確認済みです。ローカルのブラウザー統合テストは実行環境の制約で完了しておらず、審査用端末でのモーション入力も未確認です。モーション操作は端末姿勢を連続して竿角度へ写す方式ではなく、センサー動作を局面別の操作イベントへ変換する方式です。入力値は端末の持ち方やセンサー対応に左右されます。デモではPCとスマートフォンを事前接続し、センサーが使えない場合のタッチ操作も案内してください。

釣果の図鑑記録はCloudflare D1へ保存されます。一方、進行中の釣りルームとWebSocket接続はCloud Runプロセス内の状態であり、サーバー再起動後も続くものではありません。
