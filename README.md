# 技術釣り / GIJUTU TURI

![技術釣りのロゴ](./assets/gijutu-turi-logo.png)

技術の性質を、魚の生態と釣り上げるときの抵抗として体験するWeb釣りゲーム。

## 概要

「魚や説明がなくても眺めていたい海」と「目の前の海へ投げた感覚」を、PC画面とスマホの釣り竿で体験するWeb釣りゲームです。

- 画面いっぱいの3D海面、空の反射、緩やかな波。カメラは水中に入りません。
- 押してためる → ルアーの飛行 → 着水・波紋 → アタリを待つ → 回収。
- PC画面とコントローラー画面をWebSocketで同期。実際の接続に合わせて状態を表示します。
- スマホのモーション入力と、センサーを使えない場合のタッチ操作。
- あそびかた・図鑑は必要なときだけ開くダイアログです。
- 音は明示的にオンにした場合だけ再生。PWA用manifestと静的アセットキャッシュを用意しています。

画面UIはReact + Viteで管理し、既存のHTML/CSSの見た目・ID・クラスを維持しています。
Three.jsの海面描画と独自シェーダーは直接制御のまま残し、WebSocketのOcean状態機械と分離しています。ゲーム判定はサーバーを唯一の正とし、クライアントは受け取った状態を描画します。
Go魚を釣り上げた次の釣行ではDockerクジラが登場します。魚種ID・捕獲イベント・図鑑表示は共通の魚種マスタから連動し、SQLiteにプレイヤー別で記録します。Dockerクジラは掛かった直後に重く引き、CSS fishは同じ形状のまま状態ごとに色・模様・発光を変えます。
旧試作の画面は整理し、現行の海UIとOcean用バックエンドを本体として扱います。

## 起動

### Go魚のモデル確認

`npm run dev` 起動後、[Go魚の3Dプレビュー](http://127.0.0.1:8787/go-fish.html)で形状を確認できます。
ドラッグで回転、スクロールで拡大。全身・真横・正面・ディテールの切り替え、一時停止、1→7匹の分岐表示に対応しています。
本編の海には未獲得の魚を表示しません。造形の参照先と実装範囲は [docs/go-fish-design.md](./docs/go-fish-design.md) に記録しています。

### Dockerクジラのモデル確認

`npm run dev` 起動後、[Dockerクジラの3Dプレビュー](http://127.0.0.1:8787/docker-whale.html)で形状を確認できます。本編ではGo魚を捕獲して「もう一度、海へ」を押すと、次の釣行がDockerクジラになります。逃げた場合は同じ魚種に再挑戦します。
魚種ごとのデモ入口も用意しています。`/gofish` はGo魚、`/dockerwhale` はDockerクジラ、`/cssfish` はCSS fishから開始します（例: `http://127.0.0.1:8788/dockerwhale`）。`/docker` は短い互換エイリアスです。以前の `?fish=go` / `?fish=docker` も利用できますが、QRコードには正規の魚種URLが表示されます。
Dockerクジラは掛かった直後だけ強く重くなり、その後は小さな抵抗を残して落ち着きます。Go魚のような群れへの分裂や大きな横振りは起こらないため、糸の張りを見ながら引き上げられます。

### 海とサーバー

Node.js 22以降とnpmが必要です。

```powershell
npm install
npm run dev
```

[http://127.0.0.1:8788/](http://127.0.0.1:8788/) を開きます。`npm run dev` はフロントエンドとバックエンドを同時に起動します。

- `8788`: ViteのHMR付き開発サーバー。通常はこちらを開く
- `8787`: API・WebSocket・SQLiteを担当するバックエンド。モデルプレビューとヘルスチェックにも使用

開発サーバーは `0.0.0.0` で待ち受けるため、同じWi-Fi内のスマホからも接続できます。ポートを変える場合は `BACKEND_PORT` と `VITE_PORT` を指定します。

```powershell
$env:BACKEND_PORT='8791'
$env:VITE_PORT='8792'
npm run dev
```
本番相当の配信を確認する場合は `npm run build` 後に `$env:PORT='8787'; npm start` を使います。
Cloud Runのコンテナでは `Dockerfile` の設定により `PORT=8080` で起動します。Cloud Runの公開URLではポート番号を付けず、HTTPSのURLを使用します。

Cloud Runへ安価に公開する手順と、WebSocket・SQLite・料金のトレードオフは [docs/cloud-run-cheap.md](./docs/cloud-run-cheap.md) にまとめています。Vercelをフロントエンドに使う場合は、Vercelに `VITE_BACKEND_URL`、Cloud Runに `FRONTEND_ORIGIN` を設定します。Cloud RunではHTTPSのURLが発行されるため、PCに表示したQRをスマホで読み取る運用に向いています。

## 魚種別URL

PCで次のURLを開くと、最初に登場する魚種を固定できます。QRコードから開くスマホ側も同じルートになります。

| URL | 最初の魚 | 用途 |
| --- | --- | --- |
| `/` | 通常出現する魚種からランダム | 通常のゲーム入口。ルーム作成時に1匹を抽選 |
| `/gofish` | Go魚 | Go魚から始めるデモ |
| `/dockerwhale` | Dockerクジラ | 重い引きを確認するデモ |
| `/cssfish` | CSS fish | 状態による見た目の変化を確認するデモ |
| `/?fish=k8s` | K8sレヴィアタン | 二つの影を従える魚のデモ。通常抽選には含まれません |
| `/docker` | Dockerクジラ | `/dockerwhale` の互換エイリアス |

`?fish=go` と `?fish=docker` も互換用に利用できます。新しく共有するURLやQRコードでは、上表の正規パスを使ってください。`/` の抽選結果は同じルームのPC・スマホで共有され、リロードで途中変更されません。

## 操作

- 投げる: PCの「投げる」を長押しし、好きなタイミングで離します。長く押すほど遠くへ飛びます。Spaceキーでも同じ操作ができます。マウスの位置で左右の狙いを変えます。
- 待つ: 着水後はウキが沈むまで待ちます。ボタンが「合わせる」に変わったら押します。
- 回収する: アタリがない状態で「回収する」を押すと、ルアーを戻します。回収中はウキ・糸・竿先・リールが同じ進行度で動き、約0.95秒後に次のキャストへ戻ります。
- 巻く: 魚が掛かったら「巻く」を押している間だけ巻きます。糸の張りが赤くなったら離して緩めます。PCでは `R` キーでも巻けます。
- スマホで釣る: 「スマホを接続」からQRコードを表示し、スマホのカメラで読み取ります。PCとスマホが同じ海の部屋に接続され、スマホ側の操作がPCの竿へ反映されます。投げるときは振り、魚が掛かったらスマホを回すとリールを巻けます。画面のリールも使えます。
- 結果画面: 釣れた場合は「もう一度、投げる」、逃げられた場合は「もう一度投げる」で再開します。通常ルートでは捕獲後に魚種が進み、魚種別URLでは最初の魚種だけが固定されます。
- 右上: 音の切り替え。

ローカル開発ではQRコードにPCのLAN内IPアドレスを自動的に埋め込みます。PCとスマホを同じWi-Fiに接続し、ファイアウォールで8788番ポートへの接続を許可してください。本番のCloud Run/Vercelでは、現在開いているHTTPSのドメインを使うため、ローカルIPや8788番ポートは使いません。
実機のモーション入力には、両端末からアクセスできるHTTPS環境とセンサー許可が必要です。
HTTPのローカル接続ではタッチ操作を利用できます。モーションセンサーを使う場合は、両端末からアクセスできるHTTPS環境が必要です。
オフラインでは海の表示用アセットを利用できますが、キャスト同期にはサーバー接続が必要です。

## 状態同期の設計

- `OceanFishingGame` が魚の出現、アタリ、合わせ、格闘、捕獲、逃走、回収の状態遷移をサーバー側で判定します。
- `ocean-room.ts` が20Hzでゲームを進め、PC画面とスマホへ同じスナップショットを配信します。スマホ接続中はスマホを操作担当にし、PC側の操作との競合を避けます。
- Three.js側は `TackleStateStore` に受け取った状態を保持し、表示専用の補間だけを行います。回収時の進行度はサーバー時刻の `retrieveAt` から一度だけ導出し、ウキ・糸・竿・リールで共有します。
- 捕獲イベントはサーバーのルームからSQLiteへ一度だけ記録します。フロントエンドは捕獲後に図鑑を再読込するだけで、捕獲APIを二重送信しません。

## 検証

```powershell
npm run typecheck
npm test
# サーバー起動中に別のターミナルから実行
npm run test:ocean
npm run test:fish
npm run test:whale
```

`test:ocean` は公開アセット、非公開パス、魚種指定の検証、コントローラー接続、キャスト・着水・回収、連打・不正入力、切断時の状態を検証します。

## 主な構成

- `src/client/App.tsx`: Reactで構成した海・コントローラー・図鑑UI
- `src/client/useOceanRuntime.ts`: WebSocket、入力、音、図鑑APIを束ねるランタイム
- `src/rendering/*.ts`: Three.jsの海面・魚・クジラ・竿・糸・図鑑プレビュー
- `src/viewers/*.ts`: Go魚 / Dockerクジラの単体モデルビューワー
- `scripts/*.ts`: 開発サーバー起動と統合・形状検証スクリプト
- `vite.config.ts`: Reactクライアントを `dist/client` に出力する設定
- `index.html` / `ocean.css`: 海とコントローラーのUIシェルと既存ビジュアル
- `src/rendering/ocean-scene.ts`: Three.jsの海面・ルアー・糸・着水表現（Reactから命令的に利用）
- `ocean-app.js`: Viteが生成する本番クライアントバンドル
- `src/ocean-room.ts`: キャスト体験専用のサーバー状態管理
- `src/ocean-game.ts` / `src/ocean-room.ts`: 海の釣り状態機械とWebSocketルーム
- `src/fish-species.ts`: 魚種ID、モデル、図鑑、ルートで共有する魚種レジストリ
- `src/rendering/tackle-state.ts`: サーバー状態を表示用スナップショットへ変換する境界
- `src/collection-db.ts`: SQLiteの魚種マスタ・捕獲記録・重複防止イベント
- `vendor/`: Three.js配布ファイルとライセンス（外部配布物なのでJSのまま固定）

## 図鑑DB

図鑑はSQLiteを使います。初回起動時に `data/gijutu-turi.sqlite` を作成し、魚種マスタをシードします。
プレイヤーIDはブラウザごとに生成し、捕獲イベントはイベントキーで重複登録を防ぎます。
保存先を変える場合は `.env` の `GIJUTU_DB_PATH` を指定してください。

キャスト用ルームは最大128個、1ルーム8接続、無人になって30分後に回収されます。
ルームのURLは、その海を操作できる共有リンクです。第三者へ公開しないでください。
